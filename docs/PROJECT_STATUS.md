## How to read this tracker

- Current task IDs follow [the task-ID mapping](TASK_ID_MAPPING.md). Legacy IDs
  remain unchanged in historical GitHub references, PR titles, branch names,
  commit messages, test reports, evidence filenames, and original acceptance
  records.
- **Verified** means checked against the fetched repository, a worktree available in the Work environment, or the linked GitHub PR/workflow page at snapshot time. A Work environment worktree or path may be isolated infrastructure and may not exist on the owner's local Windows computer; local accessibility must be verified separately. **Reported** means stated in the referenced [MAIN CHAT](chatgpt-conversation://6afab017-025c-83e8-8065-7a4f352c3ae8), an agent report, or a task document without fresh execution here. **Unknown** means no sufficient current evidence.
- **Design approved**, **implemented**, **automated checks passed**, **packaged Windows acceptance**, **owner accepted**, and **merged** are different milestones. A green workflow does not imply installed-app acceptance; a merge does not imply owner acceptance.
- This document coordinates work. `DESIGN.md` holds approved component behavior, `UI_INVENTORY.md` records UI slice status, `ROADMAP.md` holds backlog priorities, and task documents hold detailed evidence. Historical statements in those files can lag merged GitHub history; do not silently treat them as current.
- Private ChatGPT conversation links are historical/reporting references and may not be portable or accessible to future coding agents. Preserve approved behavior in repository design specifications rather than relying on a private conversation as the only source.
- Product boundary: local-first Windows application; training-plan intake on merged `main` is JSON **1.1 only** and saves a draft without activation. JSON 1.2 is confined to unmerged B08.1 work (legacy T08.1). Source files, FIT bytes, and original planned values must remain intact.

## Sources, conflicts, and update protocol

- **Source priority for current state:** fetched `origin/main` and linked GitHub PR/workflow pages; then cleanly identified Work environment state; then approved specifications; then agent/chat reports. Work environment paths and worktrees are not evidence that the same paths exist on the owner's local Windows computer. Keep a dated citation when a status changes. A PR description is evidence of a reported test, while a completed workflow is evidence the hosted job ran.
- `ROADMAP.md` on current `main` still calls legacy T07, T06 and earlier work “Testing” on old branches, lists FIT Review confirmation as absent, and retains old test counts. Those lines describe earlier snapshots, not a fresh current implementation audit. `README.md` also retains workbook-import wording despite the JSON 1.1-only intake boundary; do not use it to expand import scope. `docs/T07_WINDOWS_ACCEPTANCE.md` preserves a pre-execution approval sequence even though later T07 workflows ran. Detailed corrections should be scoped separately.
- Recheck open PRs, workflow conclusions, fetched `origin/main`, and relevant worktree status before every update. For each item record **as-of date, evidence link/SHA, owner, branch/PR, next action, dependency/blocker**, and each acceptance column separately. Mark unverified claims “reported”; never convert a prior pass into current acceptance.
- An approved standalone component specification is valid evidence of prior design approval, including for F1. Reconcile the applicable approved decisions into `DESIGN.md`, and update `UI_INVENTORY.md` and `ROADMAP.md`, before milestone acceptance/merge; the repository records do not need to imply that implementation began without approval. Mark **Complete** only after specification, implementation, relevant tests, verification result and explicit owner acceptance are recorded. Record merge separately, and merge to `main` only after explicit owner approval.
- Keep personal workbooks, FIT files, databases, backups, credentials, generated installers and normal installed-app data out of this document and Git. Preserve all active worktrees. This tracker should be updated in a scoped docs branch/PR after review, without overwriting parallel changes.
